# Общая схема и исполняемые правила CC

Откройте [локальный просмотрщик](generated/index.html) браузером: двойной клик по
`docs/generated/index.html`. Интернет, сервер и расширения браузера не нужны.
При переносе сохраните папки `generated` и `assets` рядом. Исходный Mermaid
доступен под каждой схемой; рядом лежат `.mmd` и [таблица правил](generated/workflows.md).

В начале — [общая схема CC](generated/control-center.mmd) и ссылки на детали:
публикацию Unified/Gate, статусы, доступность действий, операции 1C Database
и импорт/экспорт CF/CFE. Весь просмотрщик поставляется в portable-папке `docs`.

Пересоздать схемы после сборки: `.agents\export-workflows.ps1`.
Пересоздать и открыть: `.agents\export-workflows.ps1 -Open`.
Проверить актуальность без записи: `.agents\export-workflows.ps1 -Check`.
Обычные Debug/Release-сборки проекта (включая Build в Visual Studio) генерируют
документацию автоматически и копируют просмотрщик в `docs` рядом с EXE.
Portable-сборка делает то же самое. Ошибка генерации завершает сборку с ошибкой;
smoke проверяет совпадение. Фоновые design-time сборки IDE и изолированные self-test
сборки не изменяют документацию репозитория.

Постоянная ссылка — `docs/generated/index.html`; она закреплена в `AGENTS.md`.
После следующей сборки достаточно обновить открытую страницу браузера.

Обзор связей строится из типизированной навигационной карты
`ControlCenterArchitecture` с проверяемыми компилятором ссылками на классы.
Это карта компонентов, не полная диаграмма исполнения. Детальные схемы
строятся из **реально исполняемых моделей**:

- `McpWorkflowRules` — условия кнопок/пакетных действий и базовая подпись статуса.
- `OneCDatabaseOperationLifecycle` — переходы операций 1С, исполняемые Stateless.
- `McpEndpointRules` — включение HTTP-публикации независимо от статуса процесса.
- `DesignerBinaryRequest` / `DesignerBinaryRules` — порядок и проверки CF/CFE,
  экспортируемые отдельным сервисом 1C Database.

Это начальное покрытие, не полная карта приложения: механизм групп хранилища
остаётся отдельным заданием на разработку, health,
транспорт и остальные процессы пока не представлены целиком. Получение фактов
из ОС/файлов проверяется отдельно от правил. Автогенерация не заменяет тесты.

Зависимости: [Stateless 5.20.1](https://github.com/dotnet-state-machine/stateless)
(Apache-2.0), [Mermaid 11.12.2](https://github.com/mermaid-js/mermaid) (MIT).
Mermaid хранится локально только для документации и не включается в EXE.
