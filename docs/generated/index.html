Общая схема MCP Control Center

CC управляет установкой, процессами и публикацией. Unified и отдельные Gate обращаются к внутреннему HTTP MCP. 1C Database — отдельный сервис, не часть EXE контроллера.

Unified и отдельные внешние порты

McpEndpointRules: одинаковые правила, независимые настройки. Порт 0 отключает публикацию, но не процесс MCP. Unified не зависит от внешнего Gate каждого MCP.

Queue — очередь; ProcessStarted — очередной процесс; Succeed / Fail — завершение; DeadlineExpired — явный предел времени; Cancel — отмена; Inactivity — подтверждённый простой. Health MCP — отдельная проверка, не состояние этой операции. Исходный stateDiagram Stateless; выше — тот же граф переходов в представлении flowchart.

Доступность действий

McpWorkflowRules.Actions → McpActionPolicy → MainForm. Условие истинно — кнопка доступна; ложно — недоступна. Это не заменяет проверки непосредственно при исполнении.

IDДействиеУсловие
MCP01Start((установлен И НЕ (процесс жив)) И есть команда запуска)
MCP02Stopпроцесс жив
MCP03Install((НЕ (установлен) И НЕ (установка завершилась ошибкой)) И есть источник установки)
MCP04Reinstall(((установлен ИЛИ установка завершилась ошибкой) И НЕ (процесс жив)) И есть источник установки)
MCP05RemoveFiles(((установлен ИЛИ установка завершилась ошибкой) И НЕ (процесс жив)) И есть источник установки)
MCP06Editвсегда
MCP07DeleteНЕ (процесс жив)
MCP08UserCommand(установлен И (НЕ (процесс жив) ИЛИ команда разрешена при работающем MCP))
MCP09BatchStart(((Active включён И установлен) И НЕ (процесс жив)) И есть команда запуска)
MCP10BatchStopпроцесс жив
MCP11BatchRestart((Active включён И установлен) И есть команда запуска)
